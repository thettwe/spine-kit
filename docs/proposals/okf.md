# Proposal: the OKF projection

**Status:** proposal, not part of the v1 build reference · **Target:** roadmap 3, beside `spine context` · **Format:** Open Knowledge Format v0.2

This was §6.8 of PLAYBOOK.md v0.11–v0.14. It is moved here so the build reference stays about v1, and so the projection can follow a standard that moved once in ten weeks without dragging the playbook with it. Nothing in v1 depends on it. Adopt it when a real consumer asks.

The governing rule it produced — *a rendering that spine reads back is a graph* — stayed in the playbook (§6.1), because it decides more cases than this one.

---

## The projection

Everything above makes the ledger rebuildable by *spine*. The Open Knowledge Format asks a smaller question — can another agent read it at all — and answers it with a directory of markdown files, one concept per file, path as identity, YAML frontmatter whose only required key is `type`. Spine-kit already holds every fact such a bundle wants, in git, hash-bound. So it emits one.

**The projection targets OKF v0.2, named exactly.** A standard is a moving object — v0.2 removed `timestamp` and moved citations into a `sources` key — so the emitter names the version it renders and the manifest pins it in `okf`, the same discipline as every other version in this design (§6.7); `--okf` refuses to run when its own target differs from the pin, exactly as `check` refuses on binary skew. v0.2 pays spine-kit back for the wait: its **provenance** family (`sources`) is a real slot for the `src` this design already requires of every node, so provenance stops travelling as prose; its **trust** family (`generated`) names the emitter; and the removal of `timestamp` suits a design that has one clock and it is the chain (§7.5). Spine emits no `stale_after` for the same reason — it cannot honestly date anything — and no `verified`, because nothing in an unsigned bundle is verified. Where a concept has an authored date, an ADR's `Date:`, it stays in the body as the authored claim it is.

The bundle root carries `index.md` with **only** `okf_version: "0.2"` in its frontmatter, that being the sole key OKF permits there; everything spine asserts about the bundle lives in `/bundle.md`, a normal typed concept where conformance is unambiguous. That placement is deliberate: OKF's conformance rules require every non-reserved `.md` to carry frontmatter with a non-empty `type`, and reserved files to follow their own structure — a binding that decides whether knowledge is current does not belong in the one file whose structure the spec constrains most and has revised once already.

`spine index --okf [<dir>]` renders the traceability graph as an OKF bundle under `.spine/cache/okf/`. It is a pure function of `--dump` over **landed, sealed facts only**, applying G10's exact exclusion set — provisional elements, `†` states rendered as `tests-approved`, volatile test results — and it carries no wall-clock time anywhere, because this design has one clock and it is the chain (§7.5). In-flight intents never appear: their `forbidden` sets and live leases are the lease registry, not the ledger, and a portable file is the wrong place for either.

| Node | Path | `type` | Fields |
|---|---|---|---|
| `intent` | `/intents/INT-042.md` | `spine.intent` | `title` from the fenced envelope's H1, `description` from its Goal, `resource` the node's `src` verbatim, `tags` the derived status and the seal's lane, strategy, mode, threat and profile; custom `spine_blob:` carries the signed blob id, which is the intent's real identity |
| `ac` | `/intents/INT-042/AC-1.md` | `spine.acceptance-criterion` | the EARS line; directory nesting *is* the `has_ac` edge |
| `adr` · `constitution` | `/adr/ADR-007.md` · `/constitution/v3.md` | `spine.adr` · `spine.constitution` | the ADR's authored `Date:` stays in the body as the authored claim it is — v0.2 removed `timestamp`, and this design has no clock to replace it with |
| `changeset` | `/changesets/<L>.md` | `spine.changeset` | base, head, tree, `report=`, `Spine-Gates`, and `M(L)` as text |
| `approval` | `/events/<scope>/<event>-<digest>.md` | `spine.signoff` · `.approval` · `.review` · `.reopen` · `.withdrawal` · `.upgrade` | `description` is the signed `reason=`; the body carries the exact signed line, its `-Sig`, and the `ssh-keygen -Y verify` command of §11. The file is named by a digest of the signed line's bytes, never by a commit sha — under squash that commit is unreachable |
| `signer` · `test` · `code_unit` | `/signers/…` · `/tests/…` · `/code/…` | `spine.signer` · `spine.test` · `spine.code-unit` | signer validity is commit ranges, never dates (G16 refuses `valid-after=`); a test's `resource` is its frozen blob's line, reachable through `L` forever |

Edges are markdown links under a heading naming the edge kind, and the sentence beside each link carries that edge's `src` in the §6.1 grammar — OKF's own rule is that link semantics come from surrounding prose. `index.md` is generated per directory, never authored; `log.md` is generated from G9's first-parent walk, and the per-intent one earns its place because the branch is deleted at landing, so the copied event lines are the only record left.

**Every bundle says where it came from — and that is all it can do.** A rendering nobody can date is the stale spec of §1 in a new format, so every bundle carries `/bundle.md`, an ordinary concept file (`type: spine.bundle`) whose frontmatter names the trunk sha rendered, the canonical `--dump` digest it is a pure function of, and the emitting release with its `dist_hash`; its body lists every emitted path with its blob id. Emission is atomic the way an upgrade is (§6.7) — rendered into staging, moved into place — so a half-written bundle never exists.

**Say exactly what that is worth.** Those fields are inside the bundle, and the bundle carries no signature: anyone rewriting it rewrites them too, and the comparison then succeeds. It detects a *stale* bundle and a *partially written* one; it detects nothing an editor chose to hide. So the rule is the one the iron rule already implies — **a cache is not verified, it is rebuilt.** A consumer holding the repository checks freshness by comparing the recorded tip with trunk's, and settles any doubt by re-running `spine index --okf`, which costs a command. A consumer *not* holding the repository cannot establish anything about the bundle at all and must treat it as hearsay: useful for orientation, never as the authority for a decision. That is not a gap in the mechanism, it is what an unsigned rendering of a signed ledger is; the signed ledger is one clone away and is the only thing that ever settles a question. Nothing here makes the bundle authoritative; it makes it *datable*, which is the least a reader is owed.

**What a bundle cannot carry, said plainly.** OKF has no signature, no hash and no attestation, and its conformance rules require a consumer to preserve unknown keys and forbid rejecting on them. A bundle therefore cannot carry this design's central guarantee and cannot be sealed. Every file points back at what is authoritative instead — `spine_blob:` on intents, `resource:` in the provenance grammar everywhere, the signed line and its verify command on every event. Two consequences follow and neither is negotiable: the bundle is **gitignored, rebuilt by one command, and never a source** — no gate, no query and no `spine` command reads it, exactly as the indexer never reads a PR description (§3.3) and nothing depends on `refs/notes/spine` (§7.4); and `--okf` refuses any destination inside the work tree that `git check-ignore` does not cover, and never runs under `--ci`. OKF's tolerance for broken links is the sharpest difference from this design, where a dangling edge is the linter (G5): the emitter never writes one, because it emits only edges the graph already has.
