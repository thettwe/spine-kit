# spine-kit specifications

`PLAYBOOK.md` is the design: what spine-kit does, why each rule exists, and which failure mode it answers. It is deliberately capped — §10 budgets what it may become — and it specifies no artifact byte-for-byte.

These documents do that. They exist because a pre-implementation audit of v0.15 found the mechanism design settled and every artifact the guarantees rest on "described by example and prose and given no grammar", concluding that two competent implementers would build binaries that could not verify each other's landings. That is exactly the property §1.1 sells, so the gap is fatal to v1 and nothing here is optional.

**The bar for every document in this directory:** someone implementing from it alone, who has never spoken to its author, produces byte-identical output to anyone else doing the same. Every field named and typed, every ordering fixed, every encoding stated, every error case given a defined behaviour, a complete worked example, and an explicit list of what is out of scope.

Where the playbook is ambiguous these documents resolve it, and each records what it resolved and why. Where a choice is genuinely the owner's it is marked **OPEN** rather than invented. Where prose here and the playbook's §11 disagree, §11 still wins — report it as a defect in one of them.

## What writing these has already found

Specifying an artifact is a different act from reviewing prose about it, and it keeps finding things seven adversarial review rounds did not:

- **The rule-5 advisory wire was spelled `G1`, colliding with a genuine G1 finding.** Under the shipped defaults the advisory is on every landing, so a signature over `wires=G1` meant *"auto-merge is unavailable"* on one landing and *"I accept these failing tests"* on another — byte-identical, and G9 could not tell them apart. Fixed in PLAYBOOK.md v0.18: the advisory is `G11`.
- **A reseal was marked as running no suite** while §5.5 seals G1 findings inside its range as `=override`, which requires G1 to have run. Fixed in v0.18.
- **G1's AC-coverage clause failed for every parametrized test**, because `verified_by` edges name function ids that never appear as a record's `id`. Fixed in `result-file.md`.
- **The reviewed-deletion path §4.3 builds was unlandable**, because the covering wire is `G8:<path>` while the finding was filed under G1.
- **Auto-merge precondition 2 was written with two conjuncts in the playbook and three in three specs.** The two-conjunct reading put `"met"` and `automerge.effective: true` into a signed, digest-covered member on every `--ci gitlab` and `--ci generic` landing, over a result file the candidate itself could have written — and it was reachable by following the playbook rather than by misreading it. Closed in v0.19; `gate-report.md` §9.25 keeps the record.
- **A published fingerprint was arithmetically impossible for any key.** `gate-report.md` §8.2 printed a 43-character unpadded base64 SHA-256 whose last character's alphabet index was not ≡ 0 (mod 4), so no 32-byte digest encodes to it — and it sat inside two published digests. Fabricated values in a vector are legitimate; a fabricated value that is *not in the value space* is a different thing, and only a round-trip catches it. All eight fingerprints in the corpus are now real keys that `ssh-keygen -lf` reproduces.
- **Two flagship vector sets were declared one landing and disagreed on four values.** `gate-report.md` §8 and `envelope-vectors.md` §8 describe the same `INT-042` landing; each note assigned the fix to the other, and neither moved for three rounds. An engineer who builds vectors first — the sane order — verifies against one, checks the other, and concludes their canonicalizer is broken. Reconciled 2026-08-27 in GR's direction on every value either document computes; `envelope-vectors.md` §15 tabulates the three that remain and says why they cannot move without regenerating that vector's signatures.
- **One release had four `dist_hash` values in four documents.** `gate-report.md` §5.3 makes `tool.version + "+" + tool.dist_hash` byte-equal to the seal's `tool=`, so two spellings of it on one landing are a contradiction, not a variation. Exactly one was computed — `manifest.md` §8.2's, with `shasum -a 256` over its published 529-byte artifact list — and it is now the corpus's.
- **A defect list that lies about what is fixed costs a reader what a real defect costs.** Round 4 found seventeen filings, "known gaps" and quoted passages describing text that had since changed: withdrawn playbook readings still cited as live, a join specified in `import-resolver.md` §12 still listed here as "specified nowhere", a `Spine-Gates` row still called self-contradictory after it was fixed. **Every filing in this set now says whether it is open or closed, and closed ones name what closed them.**

- **The seeded constitution did not parse, and the seed is what every repository starts from.** `constitution.md` §6.2 fixed the twelve rules and called them "the canonical bytes"; §3.1 and §9.1 each require one mandatory line above them, so the block rendered as printed had `# The non-negotiables` on line 1 and a blank line 2 — `missing-header`, on the first landing of every repository, against a file G4, the indexer and `--constitution` all read. Two of its three gaps are **values with no source anywhere in the corpus** and are now OPEN-10 and OPEN-11 instead of guesses. This is the third defect of one shape found while building rather than reading: **a spec that fixes an artifact's bytes, read without the spec that fixes its context** — `result-file.md` §7.1 fixed the boundary without the kernel's constraints, and §6.2 fixed the rules without the file's preamble.

## Settled by the owner, 2026-08-26

Six decisions. They are settled: propagate them, do not re-litigate them.

1. **v1 languages: Python, TypeScript/JavaScript, Dart, Swift. Kotlin is dropped.** An oracle in a `.java` file inside a mixed Kotlin/Java module is invisible to a Kotlin resolver and **nothing reports the miss** — the freeze closure is silently incomplete, G8 passes an approval it should refuse, and two equally blind implementations agree. Every other v1 obligation fails loudly. `kotlin` and the `gradle` runner token stay **reserved**; the analysis is kept as `import-resolver.md` Appendix A. Each surviving language owes a total deterministic `id → fn`, an `id → path`, and a static import resolver — all recomputed by G8 in CI, so a resolver that differs on one edge case rejects another's approvals rather than merely disagreeing. **The same rule keeps Swift and refuses one Swift shape** (`import-resolver.md` §7.3, §18 OPEN-2, closed 2026-08-27): a target compiling Objective-C or C-family sources hides an oracle from a Swift resolver identically, so it is `lang-unclassifiable` with reason `mixed-objc-target` instead of silently under-frozen. Removal and detect-and-refuse are the two outcomes one rule selects between — the refusal falls on the ordinary shape for Kotlin and on the exotic one for Swift — and neither language ships a silent hole.
2. **Provider evidence is narrowed.** A result file that cannot demonstrate a trunk-defined origin **is ingested** — checked, labelled, evaluated — and fails **auto-merge precondition 2**, which now has **three** conjuncts: the key-visibility assertion; the collector's `tool=` is the base's pin; **and** the run established a trunk-defined origin for the file. The strict reading — never ingestible — is withdrawn: it made two of the three shipped providers non-functional rather than degraded.
3. **G14 and G16 are specified in `manifest.md`**, the tenth spec. They had no algorithm in any document; every other spec had declined them as someone else's. **G13 has since joined them there** (`manifest.md` §4.8): PB §6.3 stated a dozen refusals in one sentence with no check list, no order, no status vocabulary and no verdict, and `manifest.md` had declined it by name. Three of the four Authority gates are now specified in one document; G15 is a membership test over a list §3.2 fixes.
4. **`Template:` names the variant *and* the version** — `intent@2`, `intent-change@2`, `intent-bug@2`, replacing a bare `v2`; `Spine-Signoff`'s payload is now `template=<variant>@<n>`. G4 must index the `resign` map by variant and the indexer must pick a parser by name, and neither is decidable from `v2`. Every sealed intent carries this header for ever, so it was decidable now or never. It also makes the intent header, `files[].template` and the `templates`/`resign` keys one `name@version` vocabulary.
5. **An unbounded `forbidden` set stays legal** — a human signs it and both polarities take the same patterns — and **`spine stats` gains a counter for landings whose only protected wire is a G7 hard lease**, so one intent quietly taxing every other landing is visible instead of mysterious. The counter is a predicate over a gate report's wire set, computed at read time and stored in no member.
6. **The landing subject is derived, not written**, and **G9 recomputes and checks it**. It stays **outside `envelope=`** — no digest changes, no signature moves. Residual, stated wherever it bites: the quick lane's summary is free text and **every toolkit lifecycle landing rides the quick lane**, so an uninstall can land under the subject `chore: update deps` with every signature intact.

Four earlier decisions of PB v0.19 stand unchanged: **a repository may run several runners** (a test id is qualified by the runner that collected it; the pair is the identity); **`params.timeout`**, default 1800s, read from trunk, a collector enforcing no deadline being non-conformant; **the gate report is published** to `refs/notes/spine` on every landing, no longer optional — no gate reads a note and a note is never a source; and **`params.langs`** replacing `params.lang`.
